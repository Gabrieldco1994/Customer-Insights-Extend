# Tests

## Test 1 - Block deployment until prerequisites are ready [sanity]
Viewport: desktop
Covers: environment input, Microsoft connection gate, Customer Insights prerequisite, Link to Fabric prerequisite, install-button guardrail
Description: Verifies the complete installer cannot start before authentication and both platform prerequisites are detected.

Steps:
1. Open the installer without connecting a Microsoft account
2. Review the Customer Insights and Link to Fabric sections
3. Inspect the Install solution button

Expected: Capacity, Customer Insights, and Link to Fabric show "Not checked"; both the Phase 1 Dataverse and Phase 2 Fabric actions are disabled.

## Test 2 - Guide an administrator to Customer Insights setup
Viewport: desktop
Covers: Customer Insights - Journeys prerequisite guidance, Power Platform admin center deep link, Microsoft installation documentation
Description: Verifies an administrator can reach the official setup destinations when Customer Insights is missing.

Steps:
1. Find the Customer Insights - Journeys section
2. Inspect the available setup links
3. Open each link

Expected: The page offers working links to Power Platform admin center and the official Customer Insights setup documentation.

## Test 3 - Guide an administrator to Link to Fabric setup
Viewport: mobile
Covers: Link to Fabric prerequisite guidance, workspace selection, Lakehouse selection, official maker and documentation links
Description: Verifies the Fabric prerequisite is understandable and actionable on a small screen.

Steps:
1. Find the Dataverse Link to Microsoft Fabric section
2. Inspect workspace and Lakehouse controls
3. Open the setup links

Expected: Controls remain readable, the page separates required Dataverse Link tables from Journey interaction shortcuts, and Fabric deployment remains gated until every required table and shortcut is detected.

## Test 4 - Explain installation scope and security
Viewport: desktop

## Test 5 - Show prerequisites and actionable access errors
Viewport: desktop
Covers: access prerequisites, delegated permissions, Azure requirements, Microsoft API error details
Description: Verifies administrators know what access is needed and receive the original Microsoft failure instead of a generic validation error.

Steps:
1. Read the Before you begin section
2. Review the required Dataverse, Fabric, and tenant permissions
3. Review the access-failure disclosure

Expected: The page states that Azure CLI is not required, explains when an Azure subscription is needed, requires a Dataverse System Administrator, lists licensing, Data Agent, and delegated permission requirements, and explains that validation displays the original Microsoft HTTP status, error code/message, and Request ID when available.

## Test 6 - Explain both Microsoft sign-ins
Viewport: desktop

Description: Verifies the sequential delegated sign-ins are explained without requiring an external Microsoft login during QA.

Expected: The Fabric prompt is labeled "Sign-in 1 of 2: Microsoft Fabric", provides a clickable Microsoft sign-in link, and explains that Dataverse is sign-in 2 of 2 after Fabric authentication completes.

## Test 12 - Prepare the Dataverse Link workspace automatically
Viewport: desktop
Covers: idempotent workspace creation, active capacity assignment, Power Apps handoff
Description: Verifies the prerequisite that fixed Lakehouse creation is part of the installer flow.

Steps:
1. Connect a tenant with an active qualifying Fabric capacity
2. Review the Dataverse Link section
3. Open the Power Apps handoff

Expected: The installer creates CI-JOURNEY-Integration or reuses it only when the connected user is its sole assigned principal and an Admin, assigns it to an active capacity, detects the linked Lakehouse without depending on its generated name, validates the Dataverse System Administrator role, and requires every listed Link table. It directs the administrator to Power Apps > Link data > Refresh Fabric links, then provides exact numbered instructions for Lakehouse Get data > New shortcut > Dataverse, entering the Dataverse hostname without protocol or trailing slash, creating a new organizational connection, selecting EmailSent, EmailDelivered, EmailOpened, CustomSent, and CustomNotSent, and refreshing until Ready.
